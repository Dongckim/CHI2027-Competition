# 004 저자 정보는 피드에 있는 것만, 추측 없이, 최신 리비전으로

날짜: 2026-10-22 · 단계: V0 (#1), V1 (#2) 준비

## 결정
- 프로그램 데이터는 빌드해서 쓴다 (`data/build`). 저장·가공은 공식 안내가 허용한다: 리비전 파일은 "cache those as long as you like", 파생 데이터는 같은 라이선스(CC BY-NC-SA 4.0)
- 저장 제약은 **앱 사용자(참가자)의 개인 데이터**에 대한 것이다 ("keep it in memory for the session, or in `localStorage` on the attendee's own device"). 그래서 개인 데이터는 기기에만 둔다 (CLAUDE.md 원칙 그대로)
- 저자도 개인이므로, 공개 정보라도 아래만 지킨다
  1. **피드에 있는 것만**: 외부의 사진·이메일·Google Scholar 등을 붙이지 않는다. 예외는 기관 식별용 ROR(결정 002, CC0)뿐
  2. **추측하지 않는다**: "이 분야 전문가" 같은 평가를 만들지 않는다. 소속·나라·발표 일정·논문 주제(초록 인용)만
  3. **최신 리비전으로 통째로 다시 만든다**: 피드에는 삭제 표시가 없어서, 프로그램에서 빠진 저자는 최신 리비전에서만 사라진다. 빌드는 최신 리비전만 읽고 결과를 덮어쓴다. 기기에 받은 데이터(V7)도 이전 것과 합치지 않고 교체한다
  4. **서버에 모으지 않는다**: 빌드 결과는 정적 파일로 배포. 누구를 열어 봤는지 같은 기록은 기기에만
  5. **출처 표시**: 저자 화면에 "Public programme data only", 앱에 데이터 출처 문구
- 소속이 둘 이상이면 **모든 소속**을 쓴다 (`authors[].affiliations[]`: 기관·나라 쌍). 첫 소속만 쓰면 "미국 대학 + 한국 연구소" 저자의 한국 쪽이 사라진다 (chi2026 추천 대상: 소속 둘 이상 760명, 그중 나라가 다른 223명 → 항목 100개에 나라, 320개에 기관이 더 붙음). `authors[].institutionKey`·`country`는 첫 소속으로 남겨 둔다
- 나라는 기관이 아니라 저자가 피드에 적은 소속의 `country`를 쓴다 (`authors[].affiliations[].country`). 같은 기관이 여러 나라에 있다 (chi2026 38곳: CMU 카타르, Microsoft Research 케임브리지 등). 표기는 USA·UK·South Korea만 맞추고, Hong Kong·Macao·China는 저자가 쓴 그대로 두고 검색 필터에서 묶는다

## 이유
- 공식 안내 페이지 (https://chidigitalexperience.org/programme-data/, 2026-10-22 확인)의 문구가 위와 같다
- 저자가 직접 적은 값만 쓰면 우리가 틀린 사실을 만들 일이 없다
- 기관 기준 나라는 추천 대상의 95.0%만 채우고 해외 캠퍼스를 잘못 표시한다. 저자 소속 기준은 **100%** (chi2026 2,624/2,624, chi2025 1,261/1,261)

## 남은 확인
- 공모전의 구체적인 데이터 보호 요구사항이 나중에 전달되면, "공개 프로그램의 저자 정보를 프로필로 다시 보여 주는 것"이 허용되는지 다시 확인 (미확인: 요구사항 전달 시점은 팀 내 정리 기준)
