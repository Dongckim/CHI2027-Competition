# 002 기관 이름은 ROR로 공식 기관에 연결한다

날짜: 2026-10-21 · 단계: V0 (#1)

## 결정
- 기관 이름 정리에 한해 ROR(Research Organization Registry, https://ror.org, CC0)을 CHI 공식 데이터의 보조 원천으로 쓴다. 다른 정보(논문·세션·사람)는 계속 공식 피드만 쓴다
- 피드의 기관 이름 → ROR ID로 연결하고, 같은 ROR ID인 표기는 하나의 기관(`inst:ror-<id>`)으로 합친다. 이름은 ROR 공식 이름으로 표시한다
- 사용자가 검색하는 이름(약어·별칭·현지어 이름·피드 표기)은 모두 같은 기관으로 연결된다. 저장·출력은 항상 기관 키와 ROR ID
- ROR이 못 잡는 이름은 `data/curated/institutions.json`에서 사람이 고친다 (`ror`: 이름 → ROR ID, 같은 이름이 나라마다 다르면 나라별로 / `aliases`: ROR에 없는 별칭)
- ROR 조회 결과는 `data/curated/ror-cache.json`, `ror-orgs.json`에 저장하고 커밋한다. 빌드는 네트워크 없이 이 파일만 읽으므로 결정성이 유지된다

## 이유
- 피드의 기관 표기는 2,131개(chi2026)로 오타·표기 차이가 많고 ("Carnegie Mellon Unviersity"), 첫 글자로 만든 약어는 46.9%만 맞고 241개가 여러 기관과 겹쳤다
- ROR은 상위 50곳 중 45곳을 자동으로 연결했고 오타도 잡았다 (V0 시험)
- 직접 만든 약어표는 유지비가 들고 틀릴 수 있다. ROR은 연구기관 식별의 표준이라 ACM·ORCID 등과도 맞는다
- ROR에 보내는 것은 피드에 공개된 기관 이름뿐이다 (개인 데이터 아님). 앱 실행 중에는 ROR을 부르지 않는다

## 대안
- 수동 약어표만: 처음 50곳은 되지만 4,000개 넘는 표기를 감당 못함
- 첫 글자 자동 약어: 겹침이 많아 잘못된 기관으로 연결됨
- 앱에서 ROR API 직접 호출: 사용자 검색어가 외부로 나감 → 원칙 위반

## 한계
- 회사(Google, Microsoft Research)는 ROR에 나라별 지사로만 있어 자동 연결이 안 됨 → 이름 그대로 둠
- ROR이 같은 이름의 기관 여러 곳 중 고르지 못하면(Northeastern University 미국·중국) 연결 안 함 → 나라별로 수동 지정
