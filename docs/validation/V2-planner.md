# V2 플래너

이슈: [#3](https://github.com/Dongckim/CHI2027-Competition/issues/3) · 판정: **진행 중 (플래너 부분 조건부 통과, 계약 설계 대기)** · 측정일 2026-10-21

## 가설
추천 결과로 실제로 갈 수 있는 하루 루트가 만들어진다.

## 방법
- 계약(contracts/)은 Dongchan이 Figma 초안 기준으로 먼저 설계하고 Wonjune과 논의해서 확정. 이번에는 틀만 만듦: 규칙, `npm run contracts:check`, 플래너가 필요로 하는 필드 체크리스트 ([contracts/README.md](../../contracts/README.md))
- 플래너 `app/src/planner/plan.js`: 계약과 무관한 내부 입력(`{ paperKey, relevance }` 목록 + data/build)으로 구현. 계약이 정해지면 경계에서 변환
  - 점수 = 관련도 × 현장 가치(영상 없음 1.0, 있음 0.5) − 0.01 × 이동 시간(분)
  - 하루(개최지 현지 날짜) 안에서 가중 구간 스케줄링(동적 계획법). 앞 발표가 끝나고 이동 시간 안에 다음 방에 도착할 수 있을 때만 이어 붙임
  - 같은 방은 이동 0분. 다른 방 이동 시간은 **임시값** (같은 층 4분, 다른 층 7분, 휠체어 ×1.5 + 3분). V6(#7)에서 평면도 기반으로 교체
  - 겹치는 발표는 정차마다 대안 최대 2개를 conflicts에, 원격 전용·다른 날·없는 키는 skipped에 이유와 함께
- 테스트 `tests/planner/plan.test.mjs`, 성능 `node tests/planner/bench.mjs`

## 통과 기준
1. 일부러 만든 어려운 사례 10개 정답
2. 휴대폰급 성능에서 0.1초 이내
3. chi2026·chi2025 모두 동작

## 결과
| 기준 | 결과 | 판정 |
|---|---|---|
| 어려운 사례 | **10/10** (+ 동점 처리, 이동 시간 테스트) | 통과 |
| 성능 (Apple M2, 하루 최대) | 추천 50개 **0.1ms** · 200개 **0.9ms** · 전체 논문 2,400여 개 35ms | 조건부 |
| chi2026·chi2025 | 5일·6일 모두 루트 생성, 모든 이동이 시간 안에 가능, 중복 없음 | 통과 |
| 계약 6종 + 예시 | 0/6 (설계 대기) | 미완 |

어려운 사례 10개: ① 겹치면 높은 쪽 + 대안 ② 같은 방 연속은 둘 다 ③ 다른 방 연속(틈 없음)은 하나만 ④ 틈이 이동 시간 이상이면 둘 다 ⑤ 휠체어는 같은 틈에서 하나만 ⑥ 영상 있는 발표는 절반 가치 ⑦ 관련도가 같으면 같은 방 유지 ⑧ 원격 전용·없는 키는 제외 이유와 함께 ⑨ 하루 두 번 열리는 포스터는 한 번만 ⑩ 날짜는 UTC가 아닌 현지 날짜

**성능 조건**: 휴대폰은 노트북보다 4~6배 느리다고 보면 추천 200개는 약 5ms로 충분하고, 전체 논문을 다 넣으면 약 210ms로 기준을 넘음. 계산량이 후보 수의 제곱이라서. 실제 추천은 상위 수십~수백 개라 문제없지만, **실제 휴대폰 측정은 V3 /bench에서** 해야 함.
