# V0 공식 프로그램 데이터 확인

이슈: [#1](https://github.com/Dongckim/CHI2027-Competition/issues/1) · 판정: **조건부 통과** · 측정일 2026-10-21

## 가설
ARC 기능에 필요한 정보가 공식 피드에 모두 있다.

## 방법
- `npm run data:fetch`: 5개 피드의 version.json(`?t=`)을 조회하고, 리비전 파일만 `data/raw/<edition>/rev-NNN.json`에 저장. 이미 있으면 다시 받지 않음. latest.json은 받지 않음 (리비전 파일과 내용이 같고, 리비전 파일은 바뀌지 않으므로)
- `npm run data:validate`: 공식 `/data/schema/v1.json`(draft 2020-12)으로 검사. ajv 사용
- `npm run data:build`: `data/build/<edition>/`에 meta·papers·sessions·rooms·people·topics·aliases 생성
- `node data/scripts/report.mjs`: 아래 숫자 전부 측정. 원본 결과는 [V0-data.results.json](V0-data.results.json)
- `npm test`: 시간 변환, 발표 순서, 별칭, 결정성 테스트 6개

## 통과 기준
1. 5개 피드 모두 공식 스키마 통과
2. 모든 논문에 시간·방 있음
3. 같은 입력이면 같은 결과

## 결과

### 통과 기준
| 기준 | 결과 | 판정 |
|---|---|---|
| 스키마 | **1/5 통과** (chi2025만) | 실패 → 영향 없음 |
| 논문 시간·방 (chi2026) | **1,591/1,702 = 93.5%** | 조건부 |
| 결정성 | 2회 빌드 파일 해시 **5/5 동일** | 통과 |

**스키마 실패 내용.** 공식 스키마 description에 "DRAFT, 검증되지 않음"이라고 적혀 있음. 실패 항목은 모두 ARC가 쓰지 않는 필드이거나 빌드에서 이미 처리하는 null:
- chi2026: tracks 2개에 `name` 없음 / chi2024: tracks 1개 / chi2023: tracks 3개, events 3개에 `startDate`·`endDate` 없음
- sandbox(일부러 넣은 함정): sessions 1개 `chairIds: null`, contents 1개 `tags`·`keywords: null`

**시간·방이 없는 논문 111편 (chi2026).** 모두 "Video Presentations (Papers)" 이벤트 소속인 원격 발표로, 시작=종료(0분)임. 현장 발표가 아니므로 루트에는 넣지 않고 `scheduled: false`로 표시. 다른 연도는 100%, sandbox는 1,261/1,263 (방 null 2편, 일부러 넣은 함정).

### 확인 항목
| 항목 | chi2026 | chi2025 | chi2024 | chi2023 |
|---|---|---|---|---|
| 발표 시작 = 세션 시작 + 길이×순서 (논문 세션) | **232/232** (90분, 12분) | 172/172 (12분) | 203/219 (15분) | 148/148 (14분) |
| 영상 있는 논문 | **15.9%** | 95.0% | 100% | 98.1% |
| 저자 중 시간 있는 등장 1회 이상 | **92.1%** | 100% | 99.9% | 99.8% |
| 저자 중 등장 2회 이상 (다음 등장이 의미 있음) | 42.8% | 44.2% | 43.4% | 26.3% |
| 상위 50 기관 중 흔한 약어 있는 곳 | 32 | 30 | 25 | 22 |
| 약어 자동 생성(첫 글자) 적중 | **46.9%** | 43.3% | 48.0% | 40.9% |
| 수동 약어표로 정확히 1곳 연결 | 100% | 100% | 100% | 100% |
| 주제 칩 (세션 이름 기준) | 241개 | 218 | 179 | 168 |
| 시간 있는 논문 중 칩 있음 | 100% | 100% | 87.7% | 100% |
| 포스터 시간 있음 | 82.7% (블록만) | 100% (블록) | 100% (블록) | 100% (블록) |
| 데모 시간 있음 | 100% (블록만) | 100% | 100% | 100% |
| 세션 시작이 현지 07~22시 | 100% | 100% | 100% | 100% |

- **발표 시각 규칙**: 피드에는 발표별 시각이 없음. 각 콘텐츠 종류의 `duration`(없으면 `durationOverride`)을 contentIds 순서대로 더해서 계산. 길이는 해마다 다름 (2026·2025 12분, 2024 15분, 2023 14분) → 12분을 상수로 쓰지 않음. 합이 세션 길이를 넘거나 길이가 0이면 세션 전체 블록으로 처리. chi2024의 16개는 500분짜리 "Remote Presentations" 세션 15개 + 1개
- **실제 발표 순서와 맞는지는 피드로 확인할 수 없음** (contentIds 순서가 발표 순서라는 가정)
- **영상 15.9%**: chi2026은 학회 직후에 고정된 데이터라 영상이 일부만 있음. 2027 실서비스 중에는 영상이 거의 없을 가능성이 높음 → V2의 "현장 가치" 가중치는 대부분 1.0
- **다음 등장**: `people[].appearances`(저자 발표 + 좌장, 시각순)에서 `start ≥ 지금`인 첫 항목. 계산 가능
- **기관**: chi2026 기관 이름 2,131개 (오타·표기 차이 포함, 예: "Carnegie Mellon Unviersity"). 자동 약어는 겹침이 많음 (UW → Washington·Waterloo·Warwick…, 총 241개 별칭이 여러 기관을 가리킴). 그래서 수동 약어표 `data/curated/institution-abbr.json`이 우선하고, 자동 약어는 보조로만 씀. "MIT"처럼 약어로 적힌 기관은 정식 이름으로 합침
- **주제 칩**: 세션 이름 끝의 "I", "II", "A" 등을 떼고 묶음. chi2026은 이름이 거의 다 달라서 241개 중 2개만 여러 세션을 묶음 → 칩이 너무 많음. 화면용으로는 더 큰 묶음이 필요 (V1 개념과 연결)
- **포스터·데모**: 개별 시각은 없고 세션 블록(90분)만 있음. chi2026 포스터 807개 중 140개는 원격 영상(시간 없음)

### 발견: 피드 시각은 "현지 시각을 UTC인 것처럼" 적은 값
모든 연도에서 세션 시작이 09:00Z, 11:15Z처럼 찍혀 있음. 그대로 IANA 시간대로 바꾸면 chi2024(호놀룰루)는 1.1%, chi2025(요코하마)는 49.7%만 현지 07~22시에 들어감. 현지 벽시계 값으로 보고 변환하면 4개 연도 모두 100%. → 빌드에서 실제 UTC 순간으로 변환해 저장 ([결정 001](../decisions/001-feed-times-are-venue-wall-clock.md)). 예: chi2026 "Blind and Low-Vision Interaction" 피드 값 11:15Z → 저장 09:15Z → 마드리드 표시 11:15.

## 판정
**조건부 통과.** ARC에 필요한 정보(시간·방·저자·기관·세션)는 현장 발표 전부에 있음. 조건:
1. 공식 스키마는 초안이라 4/5 피드가 실패. 실패 필드는 빌드가 처리함. 스키마가 확정되면 다시 검사
2. 원격 전용 발표(chi2026 논문 111편, 포스터 140편)는 시간·방이 없음 → 루트 제외, "원격"으로 표시
3. 발표별 시각은 계산값 (실제 순서 미확인)
