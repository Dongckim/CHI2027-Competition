# 학습 리포트 — 합성 질의 파인튜닝 + 온디바이스 증류

목표: **서버·인터넷 없이 폰/브라우저 안에서 돌아가는 추천 모델**을 학습으로 만든다.

## 파이프라인

| 단계 | 내용 | 스크립트 |
|------|------|----------|
| 1. 합성 라벨 생성 | Qwen2.5-7B-Instruct가 논문마다 "이 논문을 찾을 법한 연구주제 질의"를 생성 (영어 3 + 한국어 2) → **12,470개 (질의, 논문) 쌍**, 2,502편 | `scripts/gen_queries.py` (A6000, 14분) |
| 2. 교사 학습 | bge-m3를 질의↔논문 contrastive loss(CachedMNRL, batch 128, 2 epoch)로 파인튜닝 | `scripts/train_retriever.py` (A6000, ~9분) |
| 3. 학생 증류 | multilingual-e5-small(118M) + 선형 헤드(384→1024)가 **질의를 교사 공간으로** 매핑하도록 학습. loss = MSE(교사 질의 벡터) + 전체 2,509편 대상 CE. 제목·초록 문장 17k개를 MSE 전용 증류 데이터로 추가. 20 epoch | 〃 (~5분) |
| 4. 경량화 | 학생 → ONNX → int8 동적 양자화 (**118MB**) | 〃 |
| 5. 하이브리드 | 기기 안에서 학생 점수 + BM25(순수 알고리즘)를 min-max 정규화 후 결합 (w=0.5, dev셋으로 선택) | `scripts/eval_hybrid.py` |

논문 벡터(2,509×1024)는 교사로 미리 계산해서 앱에 넣는다. 앱은 **질의 하나만** 작은 모델로 임베딩하면 된다.

## 평가 방법

- 논문의 20%(502편)를 학습에서 완전히 제외하고, 그 논문들의 합성 질의 2,489개로 평가
- 검색 대상은 앱과 동일하게 **전체 2,509편**
- R@k = 정답 논문이 상위 k개 안에 들 확률. 페이퍼 월드컵은 상위 8편을 쓰므로 **R@8이 핵심 지표**
- 동점 점수는 무작위 순서 기대값으로 처리 (BM25는 한국어 질의에서 전부 0점이라 이 처리가 필요)

## 결과 (held-out 질의, R@1 / R@8)

| 모델 | 전체 | 영어 | 한국어 | 크기 · 실행 위치 |
|------|------|------|--------|------------------|
| BM25 (키워드) | 0.42 / 0.55 | 0.69 / 0.88 | 0.02 / 0.04 | 알고리즘 |
| bge-m3 원본 (기존 서버 모델) | 0.66 / 0.87 | 0.70 / 0.89 | 0.59 / 0.83 | 2.2GB · 서버 |
| **bge-m3 파인튜닝 (교사)** | **0.73 / 0.92** | 0.74 / 0.93 | 0.71 / 0.90 | 2.2GB · 서버 |
| 학생 (fp32) | 0.54 / 0.85 | 0.58 / 0.88 | 0.46 / 0.80 | 470MB |
| 학생 int8 | 0.50 / 0.83 | 0.56 / 0.86 | 0.42 / 0.79 | 118MB · 기기 |

하이브리드 (held-out 질의를 논문 기준 dev/test로 반분, w는 dev에서 선택, test 1,244개 기준):

| 모델 | 전체 | 영어 | 한국어 |
|------|------|------|--------|
| 학생 int8 | 0.53 / 0.84 | 0.57 / 0.87 | 0.46 / 0.81 |
| BM25 | 0.42 / 0.55 | 0.69 / 0.87 | 0.02 / 0.05 |
| **하이브리드 (앱 최종)** | **0.63 / 0.89** | **0.75 / 0.95** | 0.46 / 0.80 |

## 해석

- **파인튜닝 효과**: 교사 R@1 0.66 → 0.73, 한국어는 0.59 → 0.71로 가장 크게 개선. 합성 라벨만으로 "진짜 학습"이 된다.
- **온디바이스**: 118MB 학생 + BM25 하이브리드가 원본 bge-m3 서버 모델과 비슷하거나 더 높은 R@8. 영어는 교사보다도 높다 (영어 질의는 초록과 단어가 겹쳐 BM25가 강함).
- **약점은 한국어**: BM25가 한국어엔 무력해서 하이브리드 이득이 없다 (R@8 0.80). 개선 후보: 한국어 증류 데이터 추가(초록 번역), 더 큰 학생(e5-base, int8 ~280MB).
- **에폭 실험**: 학생 8 → 20 epoch에서 R@8 0.813 → 0.846. 기본값을 20으로 설정.

## 영어 전용 버전 (현재 앱에 탑재)

앱과 서비스는 영어로 운영하므로, 한국어 질의를 빼고 영어 전용 학생을 따로 학습했다.

- 학생: `BAAI/bge-small-en-v1.5` (33M) + 선형 헤드, 질의 prefix `Represent this sentence for searching relevant passages: `
- 학습 데이터: 영어 합성 질의 7,506개 + 제목·초록 문장 (교사는 위의 bge-m3-chi 그대로 사용)
- 실행: `CHI_LANGS=en CHI_RUN_TAG=_en CHI_STUDENT_BASE=BAAI/bge-small-en-v1.5 CHI_STUDENT_PREFIX="..." sbatch --export=ALL scripts/train_retriever.slurm --student-only`

영어 held-out 질의 기준 (R@1 / R@8):

| 모델 | 전체 held-out (1,500) | test 절반 (750) | 크기 |
|------|------------------|-----------------|------|
| bge-m3 원본 | 0.70 / 0.89 | — | 2.2GB · 서버 |
| bge-m3 파인튜닝 (교사) | 0.74 / 0.93 | — | 2.2GB · 서버 |
| 다국어 학생 int8 | 0.56 / 0.86 | 0.57 / 0.87 | 118MB |
| **영어 학생 int8** | 0.54 / 0.86 | 0.55 / 0.87 | **34MB** |
| 다국어 학생 + BM25 | — | 0.75 / 0.95 | 118MB |
| **영어 학생 + BM25 (앱 최종)** | — | **0.73 / 0.94** | **34MB** |

→ 정확도는 사실상 동일(750개 기준 차이 0.003, 오차 범위 내)하고 모델은 3.5배 작아서 영어 학생을 채택. 앱 전체 번들은 164MB → 64MB.
브라우저 출력도 Python과 비교 검증함 (토큰 84/84 일치, 임베딩 코사인 평균 0.9987).

## 한계

- 평가 질의도 같은 LLM이 만든 합성 질의라서, 실제 사용자 질의보다 낙관적일 수 있다. 실제 사용 로그가 쌓이면 그걸로 재평가하고 재랭커(C안)를 붙이는 게 다음 단계.
- 부스 집계는 오프라인 앱에서 기기별(localStorage)로만 저장된다. 여러 사람의 집계를 합치려면 동기화 서버가 필요하다.

## 재현

```bash
sbatch scripts/gen_queries.slurm                     # 합성 질의 (Qwen 7B)
sbatch scripts/train_retriever.slurm                 # 교사+학생, split 평가 + 전체 재학습
sbatch scripts/train_retriever.slurm --student-only  # 학생만 다시
python scripts/eval_hybrid.py                        # 하이브리드 평가 (GPU)
CHI_RUN_TAG=_en python scripts/export_offline_app.py  # app/offline 번들 생성 (영어 학생)
```
